# Freitty CS Wiki

База знань Customer Support Freitty: політики, процеси, процедури, посібник КС, робочі картки, реєстр документів, інструменти, довідник, ролі, журнал ознайомлень (REG-13) і архів версій.

**Сайт:** https://freitty-cs-wiki.vercel.app — лише для робочих акаунтів Microsoft 365 компанії. Без входу сторінка не відкривається.

**Джерело правди — цей репозиторій** (рішення 6.2 журналу рішень). Сайт — лише представлення. Дані, які створює сама команда (ознайомлення, ролі, призначення, журнал), живуть у базі Neon і в репозиторій не потрапляють.

## Vercel: вхід через Microsoft і база

Усі адреси, крім `/api/*`, віддає `api/page.js`. Без сесії він перенаправляє на вхід Microsoft (застосунок **Freitty CS Wiki** в Entra, лише один тенант). Сесія — підписаний cookie на 12 годин.

Змінні проєкту у Vercel (Settings → Environment Variables):

| Змінна | Що це |
|---|---|
| `AZURE_TENANT_ID` | Directory (tenant) ID застосунку в Entra |
| `AZURE_CLIENT_ID` | Application (client) ID |
| `AZURE_CLIENT_SECRET` | Client secret (Value), позначено Sensitive. Строк дії — 24 місяці: за місяць до кінця створити новий і замінити |
| `WIKI_ADMINS` | Email-и адміністраторів вікі через кому: журнал, призначення, ролі |
| `DATABASE_URL` | Створює інтеграція Neon (Storage → Neon) |

Redirect URI в Entra: `https://freitty-cs-wiki.vercel.app/api/auth/callback`. Хто може входити — Entra → Enterprise applications → Freitty CS Wiki → Users and groups (з «Assignment required = Yes»).

Права в базі перевіряє сервер (`api/_lib.js`): відмітку про ознайомлення ставить лише сама людина, навіть адмін не може її змінити; журнал, ролі, призначення і перелік обов'язкових документів — лише адміни. Таблиці створюються самі при першому запиті.

Локальна перевірка без Microsoft і Neon: `npm install`, потім `npm run dev` → http://localhost:8766 (тестовий вхід, база в пам'яті; на Vercel цей режим вимкнено).

## Як оновити документ

1. Покласти новий PDF у `inputs/pdf/` під іменем коду. Версія береться з паспорта або рядка під заголовком: **текст без підняття версії не змінюємо** — `assemble.py` попередить.
2. `pip install -r tools/requirements.txt`
3. З кореня репозиторію (розбір інкрементальний — можна передати лише нові файли):
   ```
   python -I tools/parse_pdf.py data/docs_pdf.json inputs/pdf/POL-03.pdf
   python -I tools/assemble.py .
   python -I tools/build.py .
   ```
4. Закомітити разом із новим файлом у `data/versions/` і запушити — Vercel задеплоїть сам.

Попередня версія автоматично з'являється в «Архіві версій» з повним текстом і порівнянням по пунктах. Усі, для кого документ обов'язковий, бачать «Вийшла нова версія» і ознайомлюються знову.

## Правила змісту

- Зміст документів не вигадується і не переписується; технічне форматування — можна (CLAUDE.md пакета, правило 7).
- Числа (строки, пороги) — лише в STD.
- Нові документи спершу отримують код у реєстрі.
- Дані клієнтів у вікі не потрапляють (POL-02).

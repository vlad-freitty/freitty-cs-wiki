# SOP-2.6 Правило трьох спроб і переведення в nurture

## 1. Сфера дії

**Відкладена квота** — запит, який не можна оцінити або підтвердити на дзвінку: транспорт (через transport team), Rework (після фото), перевищення ваги, ємність хабу, нічний тариф. У даних HubSpot це кваліфікація **Channel Transfer** (~13% прийнятих дзвінків, ~21% часу вхідних розмов). Той самий порядок діє для YELLOW-запитів з Instant Book.

Процедура визначає, як відкладена квота доходить до рішення клієнта. Котирування — SOP-2.5. Строки — у STD (див. `proposals/STD-deferred-quote-timings.md`).

## 2. Порядок дій

| Крок | Дія |
|---|---|
| 1. На дзвінку | Зібрати мінімальний набір: компанія + MC/DOT, послуга, локація, дата і вікно часу, деталі вантажу, **підтверджений email**, бажаний канал. Наступний крок не повинен вимагати ще одного дзвінка |
| 2. Запис | До кінця дзвінка створити відкладену квоту: тип, обіцяний час, власник |
| 3. Вхідні дані | Транспорт → запит у transport team · Rework → посилання на завантаження фото, надіслане **під час дзвінка** · Ємність, вага, нічний тариф → запит хабу |
| 4. Квота | PRO#, розбивка, посилання на підтвердження, термін дії (SOP-2.5) |
| 5. Нагадування 1 | Немає відповіді → нагадування в каналі клієнта |
| 6. Нагадування 2 | Перед завершенням терміну дії → «квота спливає» |
| 7. Закриття | Код результату (розділ 4). Жодна квота не висить без результату довше строку STD |

**Власник:** оператор, який зробив переведення, — до кінця своєї зміни; далі квота переходить у спільну чергу відкладених звернень (разом із передзвонами SOP-1.7) і передається за SOP-1.6.

**Rework без фото:** нагадування клієнту; якщо фото не надійшли до кінця робочого дня клієнта — дзвінок.

## 3. Переведення в nurture

Після трьох дотиків без рішення (квота + два нагадування) квота закривається з кодом «Програно — немає відповіді», клієнт переходить у nurture (повторний контакт — за правилами потоку 7.0 / утримання).

## 4. Коди результату

| Код | Значення |
|---|---|
| Виграно | Створено ордер |
| Програно — ціна | |
| Програно — немає відповіді | Три дотики без реакції |
| Програно — конкурент / сам впорався | |
| Програно — не можемо обслужити | Хаб відмовив, вага, hazmat, немає перевізника |
| Повторна квота | Інша дата або умови → нова квота |

Причина фіксується за SOP-2.7.

## 5. Метрики

| Метрика | Базлайн |
|---|---|
| Конверсія відкладених квот у ордер | не відстежується системно (W11: ~50% як найкращий тиждень) |
| % квот, виданих у межах строку STD | не виміряно |
| Квоти без результату довше строку STD | невідомо; ціль — 0 |
